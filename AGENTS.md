# Space Conquistador — инструкции для агентов

Читай **первым делом** при любой новой сессии (любая модель, любой режим).

## Главный файл состояния

| Файл | Назначение |
|------|------------|
| [`docs/PROJECT_LOG.md`](docs/PROJECT_LOG.md) | **Источник правды**: решения, план, чеклисты, хронология. Обновляй при каждой существенной сессии. |
| [`docs/PLAN.md`](docs/PLAN.md) | Детальный долгосрочный план (фазы, механики, риски). Закрывай пункты в логе. |
| [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) | Стек, границы пакетов, соглашения. |
| [`docs/CURSOR_MODELS.md`](docs/CURSOR_MODELS.md) | Как точечно использовать умные модели и автоматизации. |

**Правило:** перед работой — прочитай `PROJECT_LOG.md` (секции «Текущий статус» и «Следующие шаги»). После работы — допиши запись с датой, что сделано, что осталось. **Не спрашивай пользователя** уточнения, если ответ есть в логе или плане; выбирай разумный дефолт и зафиксируй его в логе.

**Пользователь ушёл:** не писать «напиши продолжай когда вернёшься». В той же сессии закрывай все пункты «Следующие шаги»; при необходимости фоновый subagent (Task).

## Продукт (зафиксировано)

- Жанр: квиз + захват территорий (мотив Triviador / ConQUIZtador), тема — **космос / планеты**.
- Платформа: **iOS + Android** (React Native + Expo).
- Язык вопросов: **только RU** (пока).
- Мультиплеер: **отложен**; MVP — **матч против бота**.
- Монорепа: `apps/mobile`, `packages/game-core`, `content/questions`; API позже в `apps/api`.

## Стек (не менять без записи в лог)

- **npm** workspaces + **Turborepo** (установка: `npm install` в корне)
- **Expo** + **Expo Router** + **TypeScript**
- Игровая логика только в **`@space-conquistador/game-core`** (без импортов из RN)
- Состояние UI: **Zustand**
- Карта: **react-native-svg** (первая версия)

## Модели (решение пользователя, 2026-11-18)

| Ситуация | Модель |
|----------|--------|
| **Сложный узкий вопрос** (архитектура, ядро, трудный баг, API дизайн) | **Opus 5.5**, **high reasoning** (не fast) |
| **Всё остальное** | **Composer** |

Суб-агент Opus — только если ты уже на Composer и нужен один совет по сложному куску; иначе пользователь сам переключит Opus в чате.

## Автономность и режимы (разрешено пользователем)

- **Не ждать** пользователя: `npm install`, `expo start`, проверки, фиксы.
- **Режимы:** **Agent** — код и команды; **Plan** — крупные фичи / архитектура онлайна; **Debug** — сборка и рантайм. Переключай сам, без лишних вопросов.
- **Node:** если нет в PATH — `brew install node` (brew есть) или Cursor helper `…/helpers/node` + `npx`.
- **Запреты:** destructive git, коммиты без запроса, сомнительные curl|bash.
- Итог в `docs/PROJECT_LOG.md`.

См. `.cursor/rules/autonomy-and-modes.mdc`.

## Суб-агенты (экономия квоты)

| Ситуация | Действие |
|----------|----------|
| Обзор репо | **Task** → `explore`, medium |
| Залипший баг после 2 попыток на Composer | один **Opus** high reasoning |

Пользователь может поставить **одну** автоматизацию (Cursor Automations / фоновый agent) с этим репо: в промпте автоматизации указать «следуй AGENTS.md и обновляй PROJECT_LOG».

## Код

- Минимальный дифф; без лишних абстракций.
- Вопросы в `content/questions/`; в рантайме не хранить `isCorrect` в объектах, отдаваемых UI во время активного вопроса (проверка через `game-core`).
- Коммиты — **только если пользователь попросил**.
