# Мультиплеер — план

Решения пользователя (2026-11-20): комнаты по ссылке/коду, гость с ником (без паролей), сейчас 1×1, но
архитектура под 2–4 игроков. Хостинг ещё не выбран (возможно, вне РФ) — сервер переносимый: Node + Postgres в Docker.

## Архитектура

```
apps/mobile          клиент (Expo): лобби, комната ожидания, онлайн-матч; матч с ботом остаётся офлайн
apps/server          Node 22 + TypeScript: Fastify (HTTP) + Socket.IO (realtime), Postgres
packages/game-core   правила — одни и те же на клиенте (бот-матч) и на сервере (онлайн)
packages/protocol    типы сообщений клиент ↔ сервер и HTTP-ответов (общие для обоих)
docker-compose.yml   Postgres 16 на порту 5433 (не трогаем локальный 5432)
```

**Сервер авторитетный.** Только сервер держит `GameContext` с ответами и вызывает `dispatch`. Клиент шлёт намерения
(`answer`, `boost`, `pick`, `attack`, `wager`, `continue`), сервер валидирует через `dispatch` (недопустимое
действие возвращает тот же state) и рассылает новый `MatchState` всем в комнате. В `MatchState` вопросы уже лежат
как `PublicQuestion` без ответа — состояние можно отдавать клиентам целиком.

**Время.** Сервер ставит `answersAt` (пауза на чтение) и дедлайн; `elapsedMs` считает сам по времени получения
ответа. По дедлайну + 1,5 с grace сервер сам отправляет `ANSWER null` за молчащих. Разбор (`reveal`) закрывается,
когда все нажали «Дальше», либо автоматически через 8 с.

**Отключения.** Игрок может переподключиться (тот же гостевой токен) и получит текущее состояние. Если игрок
отсутствует, его ходы делает таймер: вопрос — без ответа, выбор/атака — случайный допустимый вариант через 20 с.

## Этапы

**A. game-core на N игроков** (2–4): `PlayerId` → места `"p1".."p4"`, `state.players`, столицы и щиты на каждого,
ранжирование раздела по местам (1-е — 2 планеты, 2-е — 1, остальные — 0), ход атаки по кругу, финал «Ва-банк» на всех,
победа — последний со столицей или больше всех очков. Карта генерируется/выбирается по числу игроков (2: текущая
Солнечная система; 3–4: новые раскладки). Матч с ботом работает на тех же типах (`p1` = человек, `p2` = бот).
Мобильный клиент переводится на новые типы без изменения внешнего вида.

**B1. Сервер** (`apps/server`, `packages/protocol`, `docker-compose.yml`): гостевая регистрация
(`POST /guest {nickname}` → токен), комнаты (`create` → код из 4 символов, `join`, готовность, старт хостом),
матч-цикл, таблицы `players`, `rooms`, `matches`, `match_players`, `match_events`; интеграционные тесты на
двух socket-клиентах (полный матч).

**B2. Клиент**: экран ника, «Играть с друзьями» → создать комнату / ввести код, ссылка-приглашение
(`/room/ABCD`), комната ожидания с игроками и готовностью, онлайн-матч на тех же компонентах, индикатор связи и
переподключение.

**C. Проверка**: две вкладки браузера играют матч от начала до конца; обрывы связи; три игрока (без UI-полировки).

## Локальный запуск (после B)

```bash
docker compose up -d db        # Postgres на 5433
npm run server                 # API + realtime на 3001
npm run web                    # клиент на 8081, EXPO_PUBLIC_SERVER_URL=http://localhost:3001
```
