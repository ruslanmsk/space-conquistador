# Как пользоваться моделями в Cursor (дешёво + точечно умно)

## Правило пользователя (зафиксировано)

| Когда | Модель |
|-------|--------|
| Сложный **узкий** вопрос | **Opus 5.5** + **high reasoning** |
| Всё остальное | **Composer** |

То же в `.cursor/rules/models.mdc` и `AGENTS.md`.

**Режимы (разрешено в настройках):** Agent — код; **Plan** — большие фичи; **Debug** — поломки. Агент переключает сам (`.cursor/rules/autonomy-and-modes.mdc`).

---

## Коротко: что нажать, чтобы «умная» работала, пока ты ушёл

1. **Обычная работа** — в Agent оставь модель **Composer / Fast** (дешёво).
2. **Одно умное сообщение** — в поле ввода нажми **на название модели** → выбери **Opus 5.5** или **Sonnet** → отправь **один** узкий промпт → снова переключи на Fast.
3. **«Поставил и ушёл»** — **Agents** (отдельное окно) → **New Agent** / **Automation**:
   - модель: **Fast**;
   - текст: `@AGENTS.md @docs/PROJECT_LOG.md выполни все «Следующие шаги», обнови лог. Opus только через subagent, если застрял.`
4. **Умную модель агент вызовет сам** только если в **AGENTS.md** написано «вызови Task с Sonnet/Opus» — это не отдельная кнопка у тебя, это инструкция для **Fast-агента** в фоне.

**Нельзя:** включить одну галочку «всегда подключать Opus-советника». **Можно:** Fast по расписанию + редкий ручной Opus + суб-агенты по правилам в AGENTS.

---

Квота ~$20. Цель: **одна «рабочая» модель на 90% времени**, **умная — редко и по правилам**.

## 1. Что реально можно в Cursor (без магии)

| Ожидание | Реальность |
|----------|------------|
| «Запустил Fast — он сам всегда дергает Opus» | **Нет встроенного роутера.** Оркестрация = **промпт + AGENTS.md + суб-агент Task** в Agent-режиме. |
| «Одна кнопка Advisor» | Нет отдельной кнопки; аналог — **смена модели на одно сообщение** или **Task** с другой моделью. |
| «Фоновый агент, пришёл — всё готово» | **Cursor Automations** или **Background Agent** / Cloud Agent на репо с промптом «читай `AGENTS.md`, `docs/PROJECT_LOG.md`, делай следующие шаги». |

## 2. Рекомендуемая схема для этого проекта

### Ты (ручной режим)

1. **Settings → Models** — основная модель для чата: **Composer Fast** (или аналог «fast»).
2. Обычная работа — **Agent**, модель Fast, в первом сообщении:  
   `@AGENTS.md @docs/PROJECT_LOG.md продолжай следующие шаги, обнови лог`
3. **Точечно умная** — **не меняя дефолт навсегда**:
   - в том же чате открой **выбор модели** на следующее сообщение → **Sonnet high** или **Opus 5.5**;
   - одно сообщение, узкая задача:  
     *«Спроектируй state machine фаз в `packages/game-core` — только API и типы, без UI»*  
   - ответ скопировал / попросил Fast **внедрить** отдельным сообщением.

### Агент сам (когда ты не в чате)

В **`AGENTS.md`** уже прописано: агент **сам** вызывает **Task** (суб-агент) с моделью **Sonnet high / Opus** только для:

- архитектуры `game-core`;
- бота и edge cases;
- бага после 2 неудачных фиксов.

Остальное — сам на Fast.  
**Важно:** это срабатывает, если запускаешь **Agent** с моделью, которая умеет **Task** (обычный Agent в Cursor), а не «Ask» без инструментов.

## 3. Пример промпта для автоматизации (ночь / «поставил и ушёл»)

Создай **Automation** (Agents Window → Automations):

| Поле | Значение |
|------|----------|
| Триггер | Manual / Schedule / Git push — как удобно |
| Модель | **Fast** (дешевле) |
| Инструкции | См. блок ниже |

**Инструкции (вставить в automation):**

```text
Репозиторий: space-conquistador.
1. Прочитай AGENTS.md и docs/PROJECT_LOG.md (статус, следующие шаги).
2. Выполни ВСЕ пункты из «Следующие шаги», пока не упрёшься в блокер.
3. Пиши код: логика только в packages/game-core; UI в apps/mobile.
4. Не спрашивай пользователя — дефолты из AGENTS/PLAN.
5. После работы обнови docs/PROJECT_LOG.md и чеклисты в docs/PLAN.md.
6. Умную модель используй ТОЛЬКО через Task:
   - Sonnet high — один раз на дизайн API game-core, если застрял;
   - Opus — только если баг не чинится 2 попытками.
7. npm (не pnpm). Коммиты — только если явно сказано в задаче.
```

Так **одна** автоматизация на **дешёвой** модели, а «умность» — **точечные Task**, не весь прогон на Opus.

## 4. Когда какую модель (шпаргалка)

| Задача | Модель |
|--------|--------|
| Scaffold, экраны, стили, JSON вопросов | Fast / Composer |
| Реализация по готовому дизайну из Opus | Fast |
| Спроектировать фазы матча, бот, scoring | **Opus** или Sonnet high — **1 сообщение** |
| Ревью диффа перед важным merge | Sonnet или **Bugbot** (если явно попросил) |
| «Прочитай весь репозиторий» | **Task → explore**, medium |

**Opus на $20:** ориентир **3–8 тяжёлых сессий** на MVP, не десятки.

---

## 5. Plan vs Agent

- **Plan** + Sonnet/Opus: один раз набросать фазу (например онлайн в будущем) → результат в `docs/PLAN.md`.
- **Agent** + Fast: копать реализацию по плану.

---

## 6. Ограничения

- Суб-агент **не видит** твою квоту и **не биллится отдельно «бесплатно»** — Task тоже ест usage.
- Нельзя жёстко зафиксировать «всегда Opus для файла X» в UI — только через **rules + AGENTS** и дисциплину агента.
- Если агент упорно не вызывает Task — в сообщении явно:  
  *«Если нужен дизайн game-core — вызови subagent Sonnet high, не гадай сам»*.

---

## 7. Быстрый старт для тебя сегодня

1. Открой Agent, модель **Fast**.  
2. `@AGENTS.md @docs/PROJECT_LOG.md continue`  
3. Если ответ по ядру слабый — **следующее** сообщение с **Opus**: только архитектура, потом снова Fast «implement verbatim».

Обновления этой инструкции — сюда и одной строкой в `docs/PROJECT_LOG.md`.
